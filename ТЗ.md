# Технічне завдання (StudyPlanner)

## 1. Вступ

StudyPlanner — невеликий веб-сервіс (REST API на Flask) для ведення списку навчальних завдань студента: додавання, перегляд і відмітка виконання.

## 2. Мета і задачі

- Мета: надати студентові простий інструмент для обліку навчальних завдань і дедлайнів.
- Основні задачі:
  - реалізувати REST API для створення та перегляду завдань;
  - реалізувати відмітку завдання як виконаного;
  - налаштувати версіонування (SemVer) і Git-процес (спрощений GitFlow);
  - підготувати шаблони документів для командної роботи.

## 3. Цільова аудиторія

Студенти університету, які планують лабораторні, курсові та екзамени.

Ключові сценарії:
1. Студент додає завдання з назвою та дедлайном.
2. Студент переглядає список завдань.
3. Студент позначає завдання виконаним.

## 4. Функціональні вимоги

1. **Додавання завдання** — `POST /api/tasks` приймає JSON `{"title": "...", "deadline": "YYYY-MM-DD"}`.
   Критерій приймання: повертає `201` і створене завдання з `id`; без `title` повертає `400`.
2. **Перегляд завдань** — `GET /api/tasks` повертає список усіх завдань.
   Критерій приймання: повертає `200` і JSON-масив (порожній, якщо завдань немає).
3. **Відмітка виконання** — `PUT /api/tasks/<id>/done` встановлює `done = true`.
   Критерій приймання: повертає `200` і оновлене завдання; для неіснуючого `id` повертає `404`.

## 5. Нефункціональні вимоги

- Продуктивність: відповідь API < 200 мс для списку до 1000 завдань.
- Безпека: валідація вхідних даних; у наступних версіях — авторизація через OAuth2.
- Сумісність: Python 3.10+; Windows, Linux, macOS; будь-який клієнт, що працює з HTTP/JSON.
- Логування/моніторинг: логування запитів і помилок у стандартний вивід.

## 6. Обмеження та припущення

- Технології: Python, Flask, pytest, Git.
- Для версії 1.0.0 дані зберігаються в пам'яті (без БД).
- Команда — 1 особа; термін виконання — 2 тижні (2 спринти по 1 тижню).

## 7. Інтерфейс користувача (коротко)

У версії 1.0.0 — лише REST API (перевірка через `curl` або Postman).

Мікро-флоу: `POST /api/tasks` → `GET /api/tasks` → `PUT /api/tasks/1/done` → `GET /api/tasks`.

## 8. Архітектурні рішення (високорівневі)

- Сервер: Flask-застосунок (`app.py`).
- БД: відсутня у v1.0.0 (список у пам'яті); у v1.1.0 планується SQLite.
- CI/CD: запуск `pytest` при кожному push (GitHub Actions — за бажанням).
- Деплой: локальний запуск `flask run`.

## 9. План робіт та етапи

- Ітерація 1 (спринт 1): `feature/task-api` — додавання та перегляд завдань, тести.
- Ітерація 2 (спринт 2): `feature/task-done` — відмітка виконання, тести.
- Реліз 1: оновлення CHANGELOG, злиття `develop` у `main`, тег `v1.0.0`.

## 10. Критерії приймання

- Усі функції з розділу 4 працюють згідно з описаними критеріями.
- Усі автоматичні тести (`pytest`) проходять.
- Заповнено `ACCEPTANCE_CHECKLIST.md`, оновлено `CHANGELOG.md`.

Тест-кейси:
1. `POST /api/tasks` з коректними даними → `201`.
2. `POST /api/tasks` без `title` → `400`.
3. `GET /api/tasks` → `200`, список.
4. `PUT /api/tasks/1/done` → `200`, `done = true`.
5. `PUT /api/tasks/999/done` → `404`.

## 11. Додатки

Приклад запиту:

```bash
curl -X POST http://127.0.0.1:5000/api/tasks \
     -H "Content-Type: application/json" \
     -d '{"title": "Лабораторна №1", "deadline": "2026-11-01"}'
```
